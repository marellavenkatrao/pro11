Step B6

Aggregation: Group by Genre & Count

db.books.aggregate([
  { $group: { _id: "$genre", count: { $sum: 1 } } },
  { $sort: { count: -1 } }
])
Groups by genre and accumulates document counts using $sum: 1.
Step B7

Aggregation: Average Price Per Genre

db.books.aggregate([
  { $group: { _id: "$genre", avgPrice: { $avg: "$price" } } },
  { $sort: { avgPrice: -1 } }
])
Calculates mathematical average price per genre with $avg: "$price".
Step B8

Combined Aggregation: Match, Group, Sort, Project

db.books.aggregate([
  { $match: { year: { $gt: 1900 } } },
  { $group: { _id: "$genre", count: { $sum: 1 }, avgPrice: { $avg: "$price" } } },
  { $sort: { count: -1 } },
  { $project: { genre: "$_id", count: 1, avgPrice: 1, _id: 0 } }
])
Full 4-stage pipeline: filters modern books (year > 1900), groups, sorts, and reshapes fields.
Example 1

Aggregation by Genre and Decade

db.books.aggregate([
  { $match: { year: { $gte: 1900 } } },
  { $group: { _id: { genre: "$genre", decade: { $subtract: [ "$year", { $mod: [ "$year", 10 ] } ] } }, total: { $sum: 1 } } },
  { $sort: { "_id.decade": 1 } }
])
Uses arithmetic expressions $subtract and $mod to bucket by decade.
Example 2

Find with Sorting and Limiting

db.books.find({ genre: "Dystopian" }).sort({ year: -1 }).limit(2)
Combines filter + descending sort + limit(2) in a single cursor chain.

5. VIVA VOCE QUESTIONS & COMPREHENSIVE ANSWERS

Q1: How does MongoDB lazily create databases and collections?
Answer: When you issue use library, MongoDB switches the shell context but does not immediately write to disk or create files until you insert the first document or invoke db.createCollection(). Similarly, inserting documents into an uncreated collection automatically provisions it.
Q2: What is the underlying data structure of a MongoDB index, and why is it used?
Answer: MongoDB uses B-Tree (B+ Tree) data structures for its indexes. This allows search, sequential access, insertions, and deletions in logarithmic time (O(log N)). Without an index, MongoDB must perform a COLLSCAN (collection scan), examining every document.
Q3: How does the Aggregation Pipeline differ from Map-Reduce in MongoDB?
Answer: The aggregation framework processes documents through native C++ pipeline stages (such as $match, $group, $sort, $project). It executes much faster than JavaScript-based Map-Reduce and offers declarative syntax, native memory limits (100MB per stage unless allowDiskUse: true is passed), and rich operators.
Q4: Why does pipeline stage order matter in aggregate()?
Answer: Order matters because each stage takes the output of the preceding stage as its input. For example, placing $match before $group significantly reduces the number of documents passed to grouping, drastically cutting memory and CPU usage.
Q5: What is the purpose of the $project stage in MongoDB aggregation?
Answer: The $project stage reshapes documents: it includes specific fields (field: 1), suppresses fields (e.g. _id: 0), renames keys (e.g. genre: "$_id"), and computes derived values before returning results to the client.
